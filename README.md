## 链表专题总结

### 1. 为什么经常使用虚拟头节点

如果操作可能改变真正的头节点，就需要为头节点单独编写判断。虚拟头节点位于真实头节点之前：

```python
dummy_head = ListNode(next=head)
```

这样删除、合并、交换和分组翻转都可以统一为“修改前驱节点的 `next`”。对应题目：21、23、24、25。

### 2. 反转链表必须先保存后继节点

```python
next_node = current.next
current.next = previous
previous = current
current = next_node
```

一旦执行 `current.next = previous`，原来的后继关系就被覆盖。因此必须先保存 `next_node`，否则会丢失尚未遍历的链表。

### 3. 哈希表保存的是节点对象

链表相交、随机指针和环形链表关注的是“是不是同一个节点”，而不是节点值是否相同：

```python
node_dict[original_node] = copied_node
```

两个节点即使 `val` 相等，只要不是同一个对象，就不能认为它们相交或重复。

### 4. 最小堆完成多路归并

23 题的堆元素为：

```python
(node.val, list_index, node)
```

Python 元组按照从左到右的顺序比较，因此先比较 `node.val`。当节点值相同时，再比较 `list_index`，从而避免直接比较 `ListNode` 对象。堆中始终只保存每条链表当前最前面的候选节点，所以堆大小最多为 $k$。

### 5. 归并排序为什么适合链表

148 题先通过快慢指针找到中点并断开链表，再递归排序左右两部分，最后像 21 题一样合并两个有序链表。

链表不适合依赖随机访问的排序方法，但断链和合并只需要修改指针，因此归并排序非常适合链表。

### 6. LRU 为什么需要哈希表和双向链表

146 题需要同时满足两种操作：

- 通过 `key` 在 $O(1)$ 时间内找到缓存节点；
- 在 $O(1)$ 时间内把节点移动到最近使用端，或删除最久未使用节点。

字典负责快速查找，双向链表负责维护使用顺序：

```text
head <-> 最久未使用 ... 最近使用 <-> tail
```

访问或更新节点后，将它移动到 `tail` 前；容量超出时，删除 `head.next`。

## 二叉树递归入门

94 题中序遍历的顺序是：

```text
左子树 → 当前节点 → 右子树
```

```python
def inorder(node):
    if not node:
        return

    inorder(node.left)
    result.append(node.val)
    inorder(node.right)
```

调用 `inorder(node.left)` 时，当前函数会暂停，并由系统调用栈保存当前节点和下一条待执行语句。左子树全部结束后，程序才回来记录当前节点，然后遍历右子树。

## Python 常用语法

### 字典成员判断、读取与删除

```python
if key in dictionary:
    value = dictionary[key]

value = dictionary.get(key, default_value)
value = dictionary.pop(key)
```

- `key in dictionary` 默认判断键是否存在；
- `get()` 可以在键不存在时返回默认值；
- `pop(key)` 删除指定键并返回对应的值；
- 字典可以快速找到节点，但普通字典本身不能完整实现 LRU 的节点移动操作。

### 列表作为栈

```python
stack = []
stack.append(value)  # 入栈
value = stack.pop()  # 出栈
```

栈遵循后进先出。递归遍历二叉树时，Python 会在内部维护类似的调用栈。

### `deque`：双端队列

```python
from collections import deque

queue = deque()
queue.append(value)
queue.pop()
queue.popleft()
```

列表的 `pop(0)` 需要整体移动后续元素，时间复杂度为 $O(n)$；`deque.popleft()` 可以在 $O(1)$ 时间内从左侧删除。

### `heapq`：最小堆

```python
import heapq

heap = []
heapq.heappush(heap, value)
minimum = heapq.heappop(heap)
```

堆内部并不是完全有序的，但始终保证 `heap[0]` 是最小元素。插入和弹出操作的时间复杂度都是 $O(\log n)$。

### 二维列表复制

下面的写法会让所有行指向同一个内部列表：

```python
matrix_copy = [[0] * n] * n
```

应创建相互独立的行：

```python
matrix_copy = [[0] * n for _ in range(n)]
```

复制已有二维列表可以写成：

```python
matrix_copy = [row[:] for row in matrix]
```

### 列表切片与原列表替换

```python
new_nums = nums[-k:] + nums[:-k]
nums[:] = new_nums
```

- 切片和 `+` 都会创建新列表；
- `nums = new_nums` 只改变局部变量指向；
- `nums[:] = new_nums` 才会替换原列表中的元素；
- 一次长度为 $n$ 的切片或拼接需要 $O(n)$ 时间和 $O(n)$ 临时空间。

## 当前需要注意的问题

### 2. 两数相加：Python 3 的除法

当前代码使用：

```python
plus = total / 10
```

在 Python 3 中，`/` 会得到浮点数，进位应使用整除：

```python
plus = total // 10
```

否则后续节点可能得到 `0.699...` 之类的浮点值，当前实现无法在 Python 3 下正确完成普通用例。

### 148. 排序链表：文件说明与实现不一致

文件开头同时介绍了自顶向下和自底向上两种归并排序，但当前只实现了自顶向下的 `sortList`，尚未实现注释中提到的 `sortListBottomUp` 和 `cut`。

### 234. 回文链表：示例注释需要修正

文件中的示例构造的是：

```text
1 → 2 → 3 → 4 → 5
```

它不是回文链表，因此示例输出注释应为 `False`。当前判断算法本身可以正确识别该示例。

### 240. 搜索二维矩阵 II：还不是真正的右上角搜索

当前代码会对每一行分别从右向左扫描，最坏时间复杂度仍然是 $O(mn)$。真正的右上角搜索只维护一个行、列坐标：

- 当前值大于目标值：向左移动；
- 当前值小于目标值：向下移动。

这样每次都能排除一整行或一整列，时间复杂度为 $O(m+n)$。
